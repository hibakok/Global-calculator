AGENTS.md — инструкция для ИИ и человека
Этот файл — точка входа для любого ИИ (или человека), открывшегорепозиторий Global-calculator. Прочитай его — и ты сориентируешьсяв проекте, не читая весь репозиторий.

Что это за проект
Многофункциональный калькулятор на чистом Python (только стандартнаябиблиотека). Цель — самый удобный и многофункциональный калькулятор,построенный из предельно малых и понятных методов.

Золотое правило навигации
НЕ читай весь репозиторий. Порядок входа:

docs/structure.txt — карта репозитория и план ветвей.
docs/branches/<ветвь>.txt — описание методов нужной ветви.
src/branch_<N>_<тема>.py — код только нужной ветви.
docs/method_index.txt — обратный поиск: где живёт метод.
docs/conventions.txt — правила, обязательные для нового кода.
docs/changelog.txt — что уже сделано (свежие шаги сверху).
Чтобы изменить один метод, достаточно прочитать: этот файл, файл еговетви (docs и src) и его тест. Ничего больше.

Как устроен код
Ветви: программа делится на изолированные ветви(branch_1, branch_2, ...), по одному файлу кода на ветвь.
Минимализм: каждый метод делает одну простую вещь (1–5 строк).
Композиция: сложные методы собираются из простых, как из кирпичиков(power_int собран из multiply).
Изоляция: ветвь N может использовать только ветви с номером меньше N.Запрещено: обратные и циклические зависимости.
Без сторонних библиотек: только стандартная библиотека Python.
Как добавить метод (стандартный шаг)
Одно изменение репозитория = один метод. Шаг состоит из шести действий:

Код метода — в файл своей ветви src/branch_<N>_<тема>.py.
Тесты метода — в tests/test_branch_<N>.py (unittest; обычныйслучай, граничный случай, ошибочный случай).
Описание метода — в docs/branches/branch_<N>.txt по форматуMETHOD / INPUT DATA / OUTPUT DATA / FUNCTION.
Строка в docs/method_index.txt.
Запись в docs/changelog.txt (новые шаги сверху).
Если ветвь этим методом завершена — обновить статус вdocs/structure.txt.
Как проверить себя
Локально: python -m unittest discover -s tests -v
На GitHub: каждый коммит и pull request автоматически прогоняюттесты (GitHub Actions, файл .github/workflows/tests.yml).Зелёная галочка у коммита — тесты прошли. Красный крест — сломано,смотри журнал Actions.
Чего не делать
Не увеличивать методы «на всякий случай» — только текущая функция.
Не менять поведение существующих методов без записи в changelog.
Не создавать зависимостей от будущих ветвей.
Не использовать сторонние библиотеки и eval/exec.
Не оставлять метод без описания в docs и без теста.
