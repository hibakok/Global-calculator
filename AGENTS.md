AGENTS.md — инструкция для ИИ и человека
Этот файл — точка входа для любого ИИ (или человека), открывшего репозиторий Global-calculator. Прочитай его — и ты сориентируешься в проекте, не читая весь репозиторий.

Что это за проект
Многофункциональный калькулятор на чистом Python (только стандартная библиотека). Цель — самый удобный и многофункциональный калькулятор, построенный из предельно малых и понятных методов.

Золотое правило навигации
НЕ читай весь репозиторий. Порядок входа:

docs/roadmap.txt — что делать дальше: первый пункт очереди.
docs/structure.txt — карта репозитория.
docs/branches/<ветвь>.txt — описание методов нужной ветви.
src/branch_<N>_<тема>.py — код только нужной ветви.
docs/method_index.txt — обратный поиск: где живёт метод.
docs/conventions.txt — правила, обязательные для нового кода.
docs/changelog.txt — что уже сделано (свежие шаги сверху).
Чтобы изменить один метод, достаточно прочитать: этот файл, файл его ветви (docs и src) и его тест. Ничего больше.

Как устроен код
Ветви: программа делится на изолированные ветви (branch_1, branch_2, ...); крупная ветвь делится на подветви (branch_3a_tokenizer, branch_3b_parser). По одному файлу кода на ветвь или подветвь.
Минимализм: каждый метод делает одну простую вещь (1-5 строк).
Композиция: сложные методы собираются из простых, как из кирпичиков (power_int собран из multiply).
Изоляция: ветвь N может использовать только ветви с номером меньше N. Запрещены обратные и циклические зависимости.
Без сторонних библиотек: только стандартная библиотека Python.
Как добавить метод (стандартный шаг)
Одно изменение репозитория = один метод или одна подветвь — связная группа методов, которые имеют смысл только вместе (например, токенизатор). Каждый метод в группе всё равно получает свой тест, своё описание и строку в индексе. Шаг состоит из шести действий:

Код метода — в файл своей ветви src/branch_<N>_<тема>.py.
Тесты метода — в tests/test_branch_<N>.py (unittest; обычный случай, граничный случай, ошибочный случай).
Описание метода — в docs/branches/branch_<N>.txt по формату METHOD / INPUT DATA / OUTPUT DATA / FUNCTION.
Строка в docs/method_index.txt.
Запись в docs/changelog.txt (новые шаги сверху).
Обновить очередь и статус ветви в docs/roadmap.txt.
Как проверить себя
Локально: python -m unittest discover -s tests -v
На GitHub: каждый коммит и pull request автоматически прогоняют тесты (GitHub Actions, .github/workflows/tests.yml). Зелёная галочка у коммита — тесты прошли. Красный крест — сломано, смотри журнал Actions.
Чего не делать
Не увеличивать методы «на всякий случай» — только текущая функция.
Не менять поведение существующих методов без записи в changelog.
Не создавать зависимостей от будущих ветвей.
Не использовать сторонние библиотеки и eval/exec.
Не оставлять метод без описания в docs и без теста.
Не дублировать статусы ветвей нигде, кроме docs/roadmap.txt.
