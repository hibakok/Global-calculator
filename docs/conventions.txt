================================================================
КОНВЕНЦИИ КОДА "GLOBAL-CALCULATOR"
================================================================
Обязательные правила для любого нового кода. Дополняют AGENTS.md.

----------------------------------------------------------------
1. МИНИМАЛИЗМ МЕТОДОВ

- Один метод = одна простая функция.
- Тело простого метода — 1-5 строк.
- Сложное строится из простого: power_int собран из multiply.
- Если метод разросся — разделить на два и описать оба.

----------------------------------------------------------------
2. ИМЕНОВАНИЕ

- Методы: snake_case, английские имена по смыслу:
  add, int_divide, percent, tokenize.
- Файлы кода: src/branch_<N>_<тема>.py
- Файлы тестов: tests/test_branch_<N>.py
- Файлы описаний: docs/branches/branch_<N>.txt

----------------------------------------------------------------
3. ДОКУМЕНТАЦИЯ МЕТОДА

- Docstring: одна строка на русском, начинается с глагола.
- Запись в файле ветви по формату:
  METHOD / INPUT DATA / OUTPUT DATA / FUNCTION.

----------------------------------------------------------------
4. ОШИБКИ

- Деление на ноль: ZeroDivisionError.
- Неверный диапазон аргументов: ValueError.
- Неверный тип аргументов: TypeError.
- Сообщения исключений — на русском языке.

----------------------------------------------------------------
5. ИМПОРТЫ

- Модуль src импортирует соседа напрямую:
  from branch_1_arithmetic import multiply
- Тесты подключают src сами (первые строки файла тестов):
  sys.path.insert(0, os.path.join(os.path.dirname(__file__), "..", "src"))
- Запуск тестов из корня репозитория:
  python -m unittest discover -s tests -v

----------------------------------------------------------------
6. ИЗОЛЯЦИЯ ВЕТВЕЙ

- Ветвь N может импортировать только ветви с номером меньше N.
- Циклические импорты запрещены.
- Глобальное изменяемое состояние запрещено. Когда появится ветвь
  памяти — правило пересматривается и фиксируется здесь.

----------------------------------------------------------------
7. ТЕСТЫ

- Только unittest (стандартная библиотека).
- На каждый метод: обычный случай, граничный случай, ошибочный случай.
- Плавающие результаты сравниваются через assertAlmostEqual.

----------------------------------------------------------------
8. ЗАПРЕЩЕНО

- Сторонние библиотеки (pip и любые внешние зависимости).
- eval/exec для вычисления выражений (безопасность).
- Неиспользуемый код и код «на будущее».

----------------------------------------------------------------
9. РАЗМЕР ФАЙЛОВ

- Мягкий предел файла — 400 строк, жёсткий — 500.
- Если файл ветви или тестов приближается к пределу — разделить
  ветвь на подветви: branch_3a_tokenizer.py, branch_3b_parser.py;
  описания и тесты делятся так же: branch_3a.txt, test_branch_3a.py.
- Подветвь наследует номер ветви и правило изоляции: branch_3b
  может использовать branch_3a, но не наоборот.
----------------------------------------------------------------
10. ГАРАНТИЯ ЗАВЕРШЕНИЯ ЦИКЛОВ

- Любой цикл с плавающей точкой обязан завершаться на любых
  входах, включая nan и inf (nan нельзя сравнить ни с чем:
  все сравнения с ним дают False).
- Приём: условие выхода записывать как отказ от строгого
  неравенства — not (следующее < текущее), а не
  (следующее >= текущее). Тогда nan завершает цикл, а на
  обычных числах поведение то же самое.
- Бесконечные аргументы, на которых цикл не может сойтись,
  обрабатываются явной проверкой до цикла: вернуть inf/0/nan
  или поднять исключение.
- Ряды с медленной сходимостью на границах интервала
  (например, ln_series при u = 1) отвергают границы явной
  проверкой с ValueError.
