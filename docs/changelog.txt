ШАГ 26 — 2026-11-03 — Гигиена записи о переносах строк.
  Проверка git ls-files --eol показала: блобы двенадцати файлов
  проекта (ветви 5, 6a, 6b, 7 — код, тесты и описания) и самого
  .gitattributes содержат CRLF — в том числе три файла ветви 7,
  которые запись ШАГА 25 называла переведёнными на LF. Файлы
  ветви 7 содержали CRLF с самого первого коммита (проверено по
  истории), то есть замена содержимого через веб-редактор не
  даёт LF. Причина, судя по всему: веб-редактор GitHub сохраняет
  переносы строк из буфера обмена (Windows-буфер даёт CRLF), а
  .gitattributes на веб-коммиты не влияет. Вывод: пункт гигиены
  «перевести файлы на LF заменой содержимого» неисполним
  веб-интерфейсом и удалён из очереди; чтобы очередь сохранила
  восемь пунктов, в её конец добавлен пункт «Ветвь 11,
  статистика: мода и квантили». Новая политика —
  docs/conventions.txt, раздел 11 «Переносы строк»: стандарт
  остаётся LF (.gitattributes), CRLF в существующих блобах —
  допустимый косметический долг (на тесты и CI не влияет),
  однократная нормализация git add --renormalize . — на случай,
  когда у владельца появится git CLI; файлы ради переносов не
  редактировать. Запись ШАГА 25 о переводе файлов ветви 7
  считать уточнённой настоящим шагом.
